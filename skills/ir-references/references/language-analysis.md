# 발표자 노트의 어투와 좋은 표현

## 읽기와 분석

발표자 노트를 스크립트의 원문으로 사용한다. 같은 장표의 앞뒤 노트까지 순서대로 읽는다. 실제로 읽은 노트 범위를 기록하고, 직접 본 화면은 구조 카드의 `inspected_slides`에 따로 기록한다.

- **문장 구조:** 첫 문장의 정보와 다음 문장이 더하는 이유·효과·조건을 분석한다. 문장 길이와 개수는 도구의 표기 기준 통계로 보조한다.
- **격식·어휘:** 종결어미, 저희·고객·사용자 등 주어, 전문어의 풀어쓰기, 명사 나열과 동사 중심 설명을 확인한다.
- **확신 수준:** 확인한 사실, 사례, 가능성, 계획을 어떤 표현으로 구분하는지 본다. 조심스러운 말이 많다는 이유만으로 좋은 어투라고 평가하지 않는다.
- **청중 지향:** 질문·경험 환기·보여드리기·시선 안내·행동 요청을 구체적인 원문으로 식별한다. 화면의 질문을 노트의 실제 문장으로 바꿔 적지 않는다.
- **전환:** 앞 장의 결과가 다음 장의 주어·질문이 되는지, 같은 사례·입력·단위가 유지되는지 확인한다. 직접 이어지는 장과 여러 장에 걸친 큰 흐름을 구분한다.
- **장점과 보완:** 이해를 돕는 정확한 작용을 설명하고 반복·모호한 지시어·근거 메모의 혼입·화면과 다른 인물이나 상태를 기록한다.

표본만 읽었다면 읽은 노트 번호와 범위를 정확히 기록한다. 전체를 읽지 않고 전체 어투라고 표시하지 않는다. 새 자료의 갱신에서는 전체 노트를 구간별로 읽어 완료한다. 영상의 말 빠르기·억양·표정이나 발표자의 성격을 이 자료로 분석하지 않는다.

## 표현 선정

실제 원문에서 청중의 이해·질문·전환·판단에 분명한 역할을 하는 문장을 고른다. 역할 예시는 질문형 도입, 경험 환기, 인과 설명, 기술 풀어쓰기, 시연 안내, 도입 부담 해소, 검증 범위, 시장 진입, 마무리 요청이다. 맞는 역할이 없으면 새 역할을 사용해도 된다.

각 표현에 다음을 저장한다.

- `quote`: 발표자 노트에 실제로 존재하는 연속된 원문. 문장부호도 바꾸지 않는다.
- `slide`: PPT의 물리적 슬라이드 순서. 화면 속 번호와 구분한다.
- `role`: 이 문장이 맡는 역할.
- `why_good`: 정확히 어떤 표현이 이해·전환·판단에 도움이 되는지.
- `pattern`: 적용을 위한 문장 틀. 대괄호로 바꿀 내용을 표시하고 원문 인용과 구분한다.
- `usage`: 어떤 상황과 앞뒤 장표에서 쓰는지, 무엇이 갖춰져야 하는지.
- `caution`: 실제 경험·검증된 기능·같은 비교 조건 등 재사용 시 확인할 지점.

좋은 표현의 수를 채우려고 문장을 만들어 넣지 않는다. 선별할 표현이 없으면 `expressions: []`와 이유를 저장한다. 발표자 노트가 아예 없는 자료는 언어 분석 불가를 보고하고 스크립트를 임의로 복원해 저장하지 않는다.

## 저장과 검증

구조 카드를 먼저 `record`로 저장한 뒤, 아래 형태의 JSON을 `record-language`에 전달한다. `id`와 `source`는 구조 카드와 같아야 한다. `source_sha256`는 노트를 읽을 때 확인한 PPT 해시다. `source` 명령으로 얻는다.

```json
{
  "id": "NEW01",
  "source": "PPT 발표문/새 자료.pptx",
  "source_sha256": "읽을 때 확인한 파일 해시",
  "coverage": {
    "reviewed_note_slides": [1, 2, 3],
    "scope": "세 장의 노트 전체를 읽었다. 시각 확인은 기존 카드의 범위에 한한다."
  },
  "selection_note": "원문의 이해·전환·판단 기능을 기준으로 선정한 범위와 이유",
  "tone": {
    "summary": "전체 어투",
    "sentence_structure": "문장과 정보의 배치",
    "register": "종결·주어·어휘",
    "stance": "확인 사실·가능성·계획을 표현하는 방식",
    "audience_address": "청중에게 말을 거는 방식",
    "transitions": "실제 장 번호와 연결을 포함한 흐름 분석",
    "strength": "언어적으로 도움이 되는 지점",
    "caution": "반복·모호함·불일치 등",
    "adaptation": "새 원고에 적용할 기준"
  },
  "tone_evidence": [
    {
      "slide": 1,
      "quote": "해당 노트에 실제 존재하는 원문",
      "supports": ["summary", "sentence_structure", "register"]
    },
    {
      "slide": 2,
      "quote": "추가 근거가 되는 실제 원문",
      "supports": ["stance", "audience_address", "transitions", "strength"]
    }
  ],
  "expressions": [
    {
      "id": "NEW01-E01",
      "slide": 1,
      "quote": "해당 노트에 실제 존재하는 원문",
      "role": "경험 환기",
      "why_good": "이 문장의 구체적인 작용",
      "pattern": "[바꿔 쓸 부분]을 표시한 문장 틀",
      "usage": "활용할 상황과 조건",
      "caution": "적용 전에 확인할 점"
    }
  ]
}
```

근거 문장은 해당 어투 해석을 뒷받침하도록 연결한다. 장점·확신·전환마다 어떤 장의 원문을 근거로 삼았는지 확인할 수 있어야 한다.

스킬 폴더에서 실행하는 예시다. `IR_LIBRARY_ROOT`를 사용자가 지정한 자료 폴더로 설정하고, `new-language-analysis.json`은 직접 분석해 작성한 JSON 파일로 바꾼다. 별도 `--state`를 사용했다면 모든 명령에 동일하게 추가한다.

```bash
python3 scripts/ir_library.py --root "$IR_LIBRARY_ROOT" record-language new-language-analysis.json
python3 scripts/ir_library.py --root "$IR_LIBRARY_ROOT" tone NEW01
python3 scripts/ir_library.py --root "$IR_LIBRARY_ROOT" phrases --id NEW01
python3 scripts/ir_library.py --root "$IR_LIBRARY_ROOT" report
```

저장 명령은 모든 인용이 지정 장표의 노트에 실제 있는지, 표현 ID가 중복되지 않는지, 파일이 읽은 시점에서 바뀌지 않았는지 검사한다. 변형한 문장은 `quote`에 넣으면 거절된다. 통계·검사만으로 해석의 품질이 증명되지는 않으므로 실제 문맥을 읽고 판단한다.

파일은 실제 상태 폴더의 `language/ID.json`에 별도로 저장된다. 같은 상태 폴더의 `tone-report.md`와 `expression-bank.md`는 이 데이터에서 자동으로 생성하는 읽기용 보고서다. 원문이 바뀌거나 삭제된 표현은 현재 검색과 새 보고서에서 제외한다.

## 자동 갱신의 시점

새 자료를 원본 폴더에 넣으면 **다음 스킬 실행 시** 자동 감지한다. 구조 분석, 어투 분석, 원문 표현 선정과 저장, 보고서 갱신을 스킬 작업의 일부로 수행한다. 사용자에게 같은 저장 작업을 다시 요청받을 필요가 없다. 상시 폴더 감시나 외부 AI API 호출을 설치한 방식은 아니다.
